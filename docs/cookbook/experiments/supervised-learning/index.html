SFT 对比实验

本章节用于记录基于 tcrl_infra 的 SFT 对比实验结果。实验 1-2 验证 TCRL 与 Tinker 的训练等价性；实验 3-4 通过与多个 Proxy Model（小模型）和 Oracle Model（大模型）的结果对比，展示从小模型到大模型再到 TCRL SFT 后模型的性能提升路径，验证 TCRL（chat_sl）在文本分类任务上的有效性。

实验 1：no_robots 数据集​

实验配置​

  • 模型: Qwen/Qwen3-8B-Base
  • 任务: no_robots 数据集上的 SFT 训练
  • LoRA 配置: 64 rank, 5e-4 learning rate
  • 训练配置: 64 batch size, 1 epoch, Cosine Decay
  • 训练步数: 148 steps
  • Eval 间隔: 每 20 steps

核心发现​

TCRL 和 Tinker 在 no_robots 任务上取得了几乎一致的最终性能：

  1. 最终性能相当: 测试集 NLL 仅相差 0.0025，几乎可以忽略不计。
  2. 训练动态相似: 两者的 Train NLL 下降曲线呈现出高度一致的趋势。
  3. 初始状态一致: 初始 test/nll 差异仅 0.0001，证明模型初始化和数据加载完全一致。

训练动态分析​

NLL 曲线​

  • 训练 NLL: 两者均从 ~1.78 下降到 ~1.59，差距从初始的 0.018 缩小至最终的 0.003。
  • 测试 NLL: 两者在测试集上的最终表现几乎一致（1.7037 vs 1.7062），差异 < 0.2%。

梯度范数​

  • TCRL 记录的 grad_norm 显示交替出现大值和小值的模式，训练全程稳定无发散。

结论​

在相同的超参数配置下，Tinker 和 TCRL 在 no_robots 数据集上的 SFT 训练效果几乎完全一致。最终 test/nll 差距仅 0.0025（< 0.2%），train_mean_nll 各阶段均值差距从 0.018 逐步缩小至 0.003，验证了 TCRL 框架 SFT 实现的正确性与 Tinker 的等价性。

实验 2：tulu3 数据集​

实验配置​

  • 模型: Qwen/Qwen3-8B-Base
  • 任务: tulu3 数据集上的 SFT 训练
  • LoRA 配置: 64 rank, 5e-4 learning rate
  • 训练配置: 128 batch size, Cosine Decay
  • 分析步数: 212 steps (Step 0-211)
  • 数据规模: ~7330 steps/epoch

核心发现​

TCRL 和 Tinker 在 tulu3 大规模数据集上取得了高度一致的训练表现：

  1. 初始状态完全一致: test/nll 差异仅 0.0004，证明模型初始化和数据加载一致。
  2. 训练动态相似: 各阶段 train_mean_nll 均值差异均在 0.002-0.007 范围内。
  3. Loss 计算方式一致: 两者 num_loss_tokens 均为 ~128（per-sequence 归一化），NLL 可直接对比。

训练动态分析​

NLL 曲线​

  • 训练 NLL: 两者均从初始的 ~0.79 缓慢下降到 ~0.72，下降幅度约 0.07，在前 212 步（约 2.9% 训练进度）中处于稳定学习阶段。
  • 波动模式一致: 由于 batch 数据的随机性，单步 NLL 存在较大波动（约 0.6~0.9 范围），但两者波动趋势完全吻合。

梯度范数​

  • TCRL 记录的 grad_norm 显示交替出现大值（10-170）和小值（0.1-4）的模式，可能与梯度累积或优化器状态有关，但未影响训练收敛。

结论​

在 tulu3 大规模数据集上，Tinker 和 TCRL 的 SFT 训练表现几乎完全一致。两者的 train_mean_nll 各阶段均值差异不超过 0.007，初始 test/nll 差异仅 0.0004。这证明了 TCRL 框架在大规模 SFT 任务上与 Tinker 具有等价的训练效果，验证了其实现的正确性。

:::info 训练效率说明 SST-2 数据集规模较大（67K 训练样本，文本较短），batch size 128 下 1 epoch 需要 525 步训练。两种模型的训练耗时几乎一致（~2.0h），由于输入序列较短，平均步耗时收敛在约 12.7s。8B-Base 的最终 Test NLL 更低（0.0272 vs 0.0552），而 Qwen3-8B 从极高的初始 Test NLL（26.45）快速下降到 0.0552，说明 Instruct 模型能够快速适应二分类情感任务的输出格式。 :::

  2. 大规模二分类任务上两种模型表现接近: 在 SST-2 任务中，Qwen3-8B-Base（96.33%）与 Qwen3-8B（96.79%）经 SFT 后差距仅 0.46%，远小于 SST-5 上的 15.15% 差距，进一步验证了在简单二分类任务上充足的训练数据可缩小 Base 模型与 Instruct 模型之间的差距。

  3. 从小模型到大模型的提升路径清晰: 1.5B（90.83%）→ 3B（91.86%）→ 8B SFT（96.79%），SFT 在二分类情感任务上带来稳定提升；由于二分类任务本身较简单，Proxy 小模型已能取得较高的基线准确率。

核心结论​

  1. SFT 有效超越大模型: 使用 Qwen3-8B 模型进行 TCRL SFT 后，在全部七个数据集上均大幅超越 30B 级别大模型。DBPedia 达到 99.50%（+2.80%）；THUCNews 达到 98.80%（+8.80%）；AGNews 达到 96.05%（+9.55%）；SST-2 达到 96.79%（+2.64%）；IMDb 达到 95.75%（+2.15%）；TNews 达到 69.19%（+12.65%）；SST-5 达到 58.91%，超越所有 Oracle 模型。

  2. Instruct 模型 SFT 效果因任务而异: 在英文短文本任务（SST-5、AGNews、SST-2）上 Qwen3-8B 优于 Qwen3-8B-Base；在长文本二分类任务（IMDb）和中文短文本任务（TNews）上 Qwen3-8B-Base 略优；在超大规模数据集（DBPedia）和中文长文本任务（THUCNews）上两者表现一致。不同任务的最优基座模型选择需要实验验证。

  3. 数据规模影响基座模型差距: 在超大数据集 DBPedia（560K）上差距仅 0.10%；THUCNews（46K）上差距 0.00%；AGNews（120K）上差距 0.55%；SST-2（67K）上差距 0.46%；IMDb（25K）上差距 0.75%；TNews（53K）上差距 1.20%；小数据集 SST-5（8.5K）上差距达到 15.15%。充足的训练数据是 SFT 成功的关键因素。

  4. 训练效率合理: SST-5 任务约 10 分钟，IMDb 任务约 1.6 小时，TNews 任务约 1.6 小时，SST-2 任务约 2.0 小时，AGNews 任务约 2.2 小时，THUCNews 任务约 3.1 小时，DBPedia 任务约 4.2 小时，平均步耗时 8~31s，训练效率满足实际使用需求。
