TCRL vs Tinker 训练效果对比

本文档展示了 TCRL（Tinker Cookbook RL）与 Tinker 在两个基准数据集——MATH 和 GSM8K——上的对比实验结果，均使用 Qwen3-4B-Instruct-2507 作为基础模型。实验结果表明，TCRL 与 Tinker 在训练效果上基本一致，验证了 TCRL 作为开源替代方案的有效性。

实验一：MATH 数据集​

实验配置​

  • 模型: Qwen-Qwen3-4B-Instruct-2507
  • 任务: MATH 数据集上的强化学习训练
  • LoRA 配置: 32 rank, 2e-05 learning rate
  • 训练配置: 16 group size, 64 batch size, importance sampling
  • 随机种子: 0
  • 训练步数: 188 steps

核心发现​

TCRL 和 Tinker 在 MATH 任务上取得了几乎一致的最终性能：

  1. 最终性能相当: 测试集上的最终奖励仅相差 0.0036，几乎可以忽略不计。
  2. 训练动态相似: 两者的训练奖励增长曲线、格式准确率、正确性指标都呈现出高度一致的趋势。
  3. KL 散度一致: 两者在训练过程中的 KL 散度保持在同一水平，说明 TCRL 正确实现了重要性采样和策略更新逻辑。

训练动态分析​

奖励曲线​

  • 训练奖励: TCRL 和 Tinker 的训练奖励均从 ~0.36 增长到 ~0.76，增长幅度分别为 +0.41 和 +0.38。
  • 测试奖励: 两者在测试集上的最终表现几乎一致（0.7534 vs 0.7570），说明 TCRL 没有出现明显的过拟合。

格式与正确性​

  • 格式准确率: TCRL 的最终格式准确率为 90.6%，高于 Tinker 的 85.9%，表明 TCRL 在生成格式规范方面表现更优。
  • 正确率: 测试集正确率两者分别为 76.2% 和 77.2%，差异微小。

KL 散度​

  • KL(sampler ‖ trainer): 两者的 KL 散度均维持在 0.0005 左右，表明 TCRL 正确实现了与 Tinker 一致的 KL 控制逻辑，避免了策略更新过程中的分布偏移。

策略熵​

  • TCRL 的策略熵（0.1104）略高于 Tinker（0.0869），表明 TCRL 在训练过程中保持了更好的探索性，这可能有助于避免过早收敛到次优策略。

训练效率​

  • 单步耗时（最终步）: 两者基本一致（~56s）
  • 平均耗时: TCRL 的平均步耗时为 121.3s，显著高于 Tinker 的 63.0s（加速比 1.92×）

分析: TCRL 平均耗时较长的主要原因可能是：

  1. 早期训练步骤中采样耗时较长（TCRL 使用远程 API 采样，而 Tinker 可能使用了更优化的采样策略）
  2. 缺乏某些性能优化（如异步采样、批处理优化等）

实验二：GSM8K 数据集​

实验配置​

  • 模型: Qwen/Qwen3-4B-Instruct-2507
  • 训练步数: 50
  • 日期: 2026-05-19

分析​

  1. 基线差异: 两次运行基线不同（91% vs 93%），属于正常采样波动范围，差异仅为 2 个样本。

  2. 提升幅度均很小: Tinker +2%，TCRL -1%，两者变化量都在基线波动范围内，不具备统计显著性。

  3. 训练速度: Tinker 每步约 12.3s，TCRL 约 20.0s，Tinker 快约 38%。但速度差异可能与运行时的负载、网络等因素有关。

  4. Degenerate 比例极高: 两者 degenerate 比例均在 75%~100%，绝大多数 group 内 rollout 完全相同，有效训练数据（datums）极少。这是 GSM8K 上模型已经很强的典型表现，RL 训练空间有限。

  5. 训练后期 reward 波动: 两者在 Step 36~49 附近 reward 都出现波动下降，稳定性类似。

结论​

两者在 GSM8K 上没有显著差异。 提升幅度都很小（+2% vs -1%），且均在基线采样波动范围内，不具备统计意义。根本原因在于 GSM8K 对 Qwen3-4B-Instruct-2507 已属于高准确率任务（基线 91%~93%），模型 rollout 几乎没有多样性（degenerate 比例极高），RL 训练的边际收益有限。两者表现相当。

总结与展望​

总结​

  1. 跨任务验证 TCRL 有效性: 在 MATH 和 GSM8K 两个任务上，TCRL 均取得了与 Tinker 基本一致的表现——MATH 上测试奖励差异 < 0.5%，GSM8K 上差异在基线波动范围内。这验证了 TCRL 作为开源 RL 训练框架的正确性和可用性。

  2. 训练动态高度一致: 两者的奖励增长、格式准确率、KL 散度、degenerate 比例等关键指标呈现出高度相似的趋势，说明 TCRL 正确实现了 Tinker 的核心算法逻辑。

  3. 存在优化空间: TCRL 的训练效率仍有提升空间——在 MATH 上慢约 1.9×，在 GSM8K 上慢约 1.6×。后续需结合硬件进一步优化以缩小差距。

  4. 高准确率任务的收益天花板: 在 GSM8K 这类模型已表现优异的高准确率任务上，由于 degenerate 比例极高，RL 训练的边际收益有限。这是任务-模型组合的固有特性，而非框架本身的局限。

后续工作​

  1. 性能优化: 结合硬件进一步优化 TCRL 的采样和训练流程，提升训练效率。
  2. 更多任务验证: 在更多任务上验证 TCRL 的通用性，尤其是基线准确率较低、RL 提升空间更大的任务。
  3. 功能完善: 支持更多的 Loss Functions 及训练策略，扩展 TCRL 的适用范围。
